# ماتریس امکانات Abyss Tunnel — وضعیت واقعی

این فایل برای جلوگیری از جاافتادن نیازهاست. «پیاده‌سازی‌شده» یعنی کد و تست خودکار وجود دارد؛ به‌معنای تأیید اتصال واقعی از همه اپراتورها نیست.

## امکانات پیاده‌سازی‌شده در شاخه توسعه
| بخش | وضعیت | توضیح |
|---|---|---|
| داشبورد دارک و RTL | پایه موجود | منوی همبرگری، جست‌وجو، راهنماهای کوتاه، موبایل‌پسند؛ بازطراحی هنری نهایی هنوز انجام نشده است. |
| نشانگرهای داشبورد | پیاده‌سازی‌شده | CPU/RAM/دیسک و نرخ مصرف ثبت‌شده؛ این‌ها سرعت‌سنج اینترنت مشتری یا پینگ VPN نیستند. |
| حساب‌های مدیر | پیاده‌سازی‌شده | مالک، مدیر و فقط‌مشاهده؛ ساخت/غیرفعال‌سازی حساب و بازنشانی رمز توسط مالک. |
| سرویس مشتری | پیاده‌سازی‌شده | ساخت، ویرایش، توقف/فعال‌سازی، حذف، ریست مصرف، حجم و تاریخ انقضا. |
| اشتراک مشتری | پیاده‌سازی‌شده | صفحه اختصاصی، لینک خام Base64، لینک مستقیم پروفایل، QR، وضعیت مصرف/انقضا، راهنما و بررسی خطا. |
| کلاینت‌ها و دانلود رسمی | پیاده‌سازی‌شده | لینک‌های رسمی Google Play، App Store و GitHub برای Android، iOS/iPadOS و دسکتاپ. |
| دسته‌بندی اپراتور | جزئی/محلی | مشتری می‌تواند شبکه را انتخاب کند و نتیجه هر پروفایل را روی همان دستگاه ذخیره کند؛ پروفایل‌های موفق برای همان شبکه بالاتر می‌آیند. این، مسیر اختصاصیِ از پیش بهینه‌شده برای اپراتور نیست. |
| پروفایل‌ها | پیاده‌سازی‌شده | شش پروفایل VLESS: WebSocket، HTTPUpgrade و چهار حالت XHTTP. |
| API ربات | پیاده‌سازی‌شده | scopeهای جدا، کلیدهای قابل لغو و دارای انقضای اختیاری، CRUD مشتری، تمدید، تغییر حجم، ریست مصرف و آمار. |
| مستندات API | پیاده‌سازی‌شده | Swagger و ReDoc با نشست پنل محافظت می‌شوند؛ راهنمای فارسی هم موجود است. |
| بکاپ/بازیابی | پیاده‌سازی‌شده | ZIP، بررسی سلامت SQLite و تلاش برای rollback در صورت شکست اعمال تنظیمات. |
| تبلیغ کانال | پیاده‌سازی‌شده | فقط از متغیرهای محیطی مالک؛ از پنل مشتری قابل تغییر نیست. |
| کنترل‌های امنیتی خودکار | پیاده‌سازی‌شده | نشست و CSRF، محدودسازی نرخ، اعتبارسنجی ورودی، تست XSS/نقش‌ها/API/بکاپ، Bandit و pip-audit. |

## مواردی که هنوز پیاده‌سازی یا اثبات نشده‌اند
| مورد | وضعیت دقیق | چرا جدا نگه داشته شده است |
|---|---|---|
| چندنودی واقعی | انجام‌نشده | نیاز به مدل نود، احراز هویت امن بین نودها، همگام‌سازی تنظیمات و بازیابی هنگام قطع ارتباط دارد؛ افزودن ظاهریِ گزینه بدون عامل نود واقعی درست نیست. |
| WireGuard | انجام‌نشده | نیازمند مسیر اجرایی و شبکه‌ای جداگانه است؛ پشتیبانی kernel/network روی Railway باید قبل از طراحی بررسی شود. |
| پروتکل‌های بیشتر مثل Trojan/VMess | انجام‌نشده | در این نسخه فقط پروفایل‌های VLESS فعال‌اند؛ اضافه‌کردن پروتکل باید شامل تولید کانفیگ معتبر، subscription و تست کلاینت واقعی باشد. |
| محدودیت IP/دستگاه | انجام‌نشده | به ردیابی اتصال/آدرس و اعمال قابل اعتماد روی موتور نیاز دارد؛ در حال حاضر نباید به مشتری وعده داده شود. |
| شمارش آنلاین واقعی هر مشتری | انجام‌نشده | «فعال» یعنی دسترسی سرویس روشن است، نه اینکه کاربر همین لحظه متصل باشد. |
| پینگ/سرعت واقعی مشتری | اثبات‌نشده | بررسی فعلی مسیر HTTP داخلی سرور است؛ اندازه‌گیری واقعی باید از دستگاه و اپراتور موردنظر انجام شود. |
| بهینه‌سازی خودکار اپراتورها | انجام‌نشده | به نتایج تجربی روی سیم‌کارت‌ها و مناطق واقعی نیاز دارد؛ هیچ ترتیب از پیش ساخته‌شده‌ای به‌عنوان بهترین مسیر معرفی نشده است. |
| تست نفوذ مستقل | انجام‌نشده | تست خودکار و اسکن ایستا جایگزین ارزیابی شخص ثالث نیستند. |
| استقرار Railway نهایی | عمداً انجام‌نشده | تغییرات روی شاخه جدا و PR پیش‌نویس نگه داشته شده‌اند تا پس از تکمیل ظاهر و بررسی نهایی یک‌بار منتشر شوند. |

## وضعیت CI
آخرین نسخه بررسی‌شده در این شاخه: ۳۲ تست pytest پاس شده‌اند؛ بررسی syntax جاوااسکریپت داشبورد و صفحه اشتراک، build کانتینر، smoke test مسیرهای Nginx/Xray و اسکن‌های Bandit/pip-audit موفق بوده‌اند. این نتیجه سلامت کد و مسیرهای پایه را بهتر می‌کند، اما اتصال واقعی همه پروفایل‌ها را تضمین نمی‌کند.
