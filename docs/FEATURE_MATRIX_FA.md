# ماتریس امکانات AbyssPanel — نسخهٔ یکپارچهٔ آزمایشی

این ماتریس وضعیت کد را از اتصال واقعی تفکیک می‌کند. سبز بودن تست خودکار به‌معنای کارکرد قطعی روی تمام اپراتورها و برنامه‌ها نیست.

| قابلیت | وضعیت |
|---|---|
| پنل RTL فارسی، حالت تیره، منوی همبرگری و طراحی واکنش‌گرا | پیاده‌سازی شده؛ بررسی بصری نهایی روی Railway لازم است |
| مدیریت سرویس‌ها، سهمیه، انقضا، توقف/فعال‌سازی و ریست مصرف | پیاده‌سازی شده |
| ۱۲ پروفایل پشتیبانی‌شده: ۱۰ مسیر VLESS شامل WS/HTTPUpgrade و شش مسیر XHTTP با چهار حالت واقعی (auto، packet-up، stream-up، stream-one)، به‌علاوهٔ Trojan WS و VMess WS | پیاده‌سازی شده؛ stream-up/stream-one با مسیر اصلی و جایگزین به‌صورت آزمایشی تست می‌شوند، چون Railway HTTP/1.1 edge ممکن است این حالت‌ها را محدود کند؛ Shadowsocks-WebSocket نامعتبر حذف شده است |
| یک لینک اشتراک برای مرورگر و کلاینت VPN | پیاده‌سازی شده؛ هدر استاندارد Subscription-Userinfo شامل مصرف، سقف حجم و انقضاست؛ تست واردکردن لینک در اپ واقعی لازم است |
| حساب‌های owner/admin/viewer | پیاده‌سازی شده؛ نقش مشاهده‌گر باید فقط خواندنی بماند |
| سهمیهٔ نمایندگی سلسله‌مراتبی | موجود در هسته؛ تست‌های رگرسیون حفظ شده‌اند |
| API بات با Bearer key و scope، انقضا و لغو کلید | پیاده‌سازی شده |
| Swagger و ReDoc محافظت‌شده با نشست مدیر | پیاده‌سازی شده |
| ZIP backup/restore، اعتبارسنجی دیتابیس و تلاش برای rollback | پیاده‌سازی شده؛ بازیابی روی نسخهٔ Railway باید آزمایش شود |
| پایش CPU/RAM/دیسک، نرخ مصرف ثبت‌شده و آمار گزارش‌های پروفایل بر اساس اپراتور | پیاده‌سازی شده؛ نرخ مصرف ثبت‌شده پینگ یا سرعت واقعی کاربر نیست |
| عیب‌یابی هوشمند بر اساس اپراتور، ثبت گزارش موفق/ناموفق پروفایل‌ها، پیشنهاد بر اساس گزارش‌های ۳۰ روز اخیر و تعمیر امن | پیاده‌سازی شده؛ توصیه‌ها به گزارش کاربران متکی‌اند و تست داخلی معادل پینگ واقعی تونل نیست |
| لینک‌های دانلود رسمی و راهنمای اتصال | پیاده‌سازی شده |
| محدودسازی نرخ، CSRF، نشست امن، هش رمز و اسکن وابستگی‌ها | بخشی از کنترل‌های امنیتی خودکار؛ جایگزین تست نفوذ مستقل نیست |
| WireGuard روی Railway | فعال نشده؛ این استقرار Railway مسیر عمومی HTTP/HTTPS دارد و زیرساخت UDP لازم برای WireGuard را فراهم نمی‌کند؛ کانفیگ صوری برای آن نمایش داده نمی‌شود |
| چندنودی واقعی، محدودیت IP/دستگاه و شمارش اتصال آنلاین | پیاده‌سازی نشده |
| تست واقعی همهٔ پروفایل‌ها از سیم‌کارت‌ها و مناطق مختلف | نیازمند آزمایش میدانی کاربر |
| استقرار نهایی و تأیید اتصال Railway | پس از پاس‌شدن CI و بازبینی نهایی انجام می‌شود |

## روش تست پس از انتشار
1. ورود به پنل و بررسی منوی همبرگری، صفحه‌ها و نقش‌ها.
2. ساخت یک سرویس آزمایشی با حجم/انقضای مشخص و بررسی محاسبهٔ مصرف.
3. بازکردن لینک اشتراک در مرورگر؛ سپس واردکردن همان لینک در v2rayNG/Hiddify/NekoBox.
4. تست جداگانهٔ هر ۱۲ پروفایل با VPN خاموش و سپس روشن؛ نتیجهٔ پینگ برنامه را با پینگ مسیر داخلی پنل یکی فرض نکن.
5. ساخت کلید API با scope محدود و آزمایش مجوزهای مجاز/غیرمجاز.
6. ساخت حساب viewer و اطمینان از ردشدن هر عملیات تغییردهنده.
7. دانلود بکاپ ZIP و فقط روی دادهٔ آزمایشی بررسی بازیابی.
8. اگر خطایی رخ داد، متن دقیق خطا، نام پروفایل، اپ، اپراتور و اینکه VPN روشن بوده یا نه را برای دور بعد ثبت کن.

هیچ تضمینی برای سازگاری تمام پروفایل‌ها با Railway Edge یا تمام اپراتورها وجود ندارد؛ نتیجه باید از اتصال واقعی به دست آید.
