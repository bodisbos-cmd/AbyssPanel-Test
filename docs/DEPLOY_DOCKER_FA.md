# استقرار روی سرور لینوکسی با Docker Compose

این روش علاوه بر Railway، برای VPS یا سرور لینوکسی دارای Docker Engine و Docker Compose v2 است. در این روش TLS باید در reverse proxy یا لایه ورودی سرور تنظیم شود؛ پورت داخلی برنامه 8080 است و پروفایل‌ها از دامنه HTTPS عمومی استفاده می‌کنند.

## پیش‌نیازها
- سرور x86_64 یا ARM64 سازگار با تصویر رسمی Xray، Docker Engine و Docker Compose v2.
- دامنه‌ای که به سرور اشاره کند و reverse proxy/TLS معتبر داشته باشد.
- حداقل 1 GB RAM توصیه می‌شود؛ مصرف واقعی به تعداد اتصال‌ها و ترافیک بستگی دارد.

## اجرا
1. مخزن را روی سرور دریافت کن و وارد پوشه پروژه شو.
2. فایل `.env` را از `.env.example` بساز؛ برای دامنه عمومی مقدار `BASE_URL=https://panel.example.com` را قرار بده.
3. برای دسترسی عمومی فقط HTTPS را در reverse proxy فعال کن؛ `COOKIE_SECURE=1` را حفظ کن. پورت 8080 را ترجیحاً فقط پشت reverse proxy قرار بده.
4. اجرا: `docker compose up -d --build`
5. وضعیت: `docker compose ps` و `docker compose logs -f abyss-tunnel`
6. در اولین اجرا رمز تصادفی در لاگ یا فایل داخل volume با مسیر `/data/INITIAL_ADMIN_PASSWORD.txt` ساخته می‌شود. بلافاصله وارد پنل شو و رمز را تغییر بده.
7. برای به‌روزرسانی: ابتدا از داشبورد بکاپ بگیر، سپس `docker compose up -d --build` اجرا کن.

## نگهداری و امنیت
- volume با نام `abyss_data` را حذف نکن؛ دیتابیس، کلید نشست و تنظیمات در آن نگهداری می‌شوند.
- پورت عمومی 8080 را مستقیم در اینترنت باز نگذار؛ reverse proxy با TLS، محدودسازی دسترسی و هدرهای درست تنظیم کن.
- فایل بکاپ و لینک اشتراک هر مشتری محرمانه‌اند.
- پیش از استفاده تجاری، همه پروفایل‌ها را از شبکه‌ها و دستگاه‌های واقعی آزمایش کن. بررسی مسیر HTTP از داخل پنل، به‌تنهایی پینگ یا اتصال واقعی تونل را تأیید نمی‌کند.
- این Compose برای تک‌نود است؛ کلاستر چندنودی، WireGuard و IP/device limits هنوز جزو امکانات این نسخه نیستند.
