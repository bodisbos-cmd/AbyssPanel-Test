# راهنمای نصب و انتشار Abyss Tunnel روی Railway

این راهنما برای استقرار روی Railway نوشته شده است. مخزن در حال توسعه است؛ قبل از فروش عمومی باید تمام مسیرهای اتصال با کلاینت واقعی و شبکه‌های هدف آزمایش شوند.

## ۱) آماده‌سازی GitHub
1. مخزن `bodisbos-cmd/AbyssPanel-Test` را باز کن.
2. برای نسخه فعلی توسعه از شاخه `feature/abyss-complete-platform` استفاده می‌کنیم؛ آن را با `main` اشتباه نگیر.
3. در تب Actions، اجرای workflow با نام **Tests** و **Security audit** را بررسی کن. هر دو باید سبز باشند.
4. رمزها و توکن‌های واقعی را در GitHub قرار نده.

## ۲) ساخت سرویس Railway
1. در Railway یک پروژه بساز و سرویس را از مخزن GitHub وصل کن.
2. روش build را روی **Dockerfile** بگذار.
3. در تنظیمات سرویس، Volume بساز و mount path آن را دقیقاً `/data` بگذار. دیتابیس و کلید نشست اینجاست.
4. دامنه عمومی HTTPS برای سرویس ایجاد کن. برنامه داخل کانتینر روی پورت `8080` گوش می‌دهد.
5. متغیرهای اختیاری:
   - `BASE_URL=https://دامنه-واقعی` فقط اگر تشخیص دامنه Railway درست نیست.
   - `ABYSS_CHANNEL_URL=https://t.me/نام_کانال` برای نمایش کانال اختصاصی در صفحه اشتراک.
   - `ABYSS_CHANNEL_TEXT` برای متن کوتاه تبلیغ کانال.
   - `LOG_LEVEL=INFO` برای سطح لاگ معمول.
6. برای سرویس عمومی `COOKIE_SECURE=0` تنظیم نکن؛ فقط برای تست محلی HTTP است.

## ۳) ورود اولیه و امن‌سازی
1. نام کاربری اولیه `admin` است.
2. رمز تصادفی اولیه را از فایل `/data/INITIAL_ADMIN_PASSWORD.txt` یا لاگ اولین اجرا بردار.
3. وارد پنل شو و رمز را از دکمه «تغییر رمز عبور» عوض کن. رمز جدید حداقل ۱۴ نویسه و شامل حرف و عدد باشد.
4. رمز اولیه را در پیام یا کانال عمومی نفرست. پس از تغییر، فایل رمز اولیه حذف می‌شود.
5. قبل از هر به‌روزرسانی مهم از بخش بکاپ ZIP بگیر و آن را بیرون از سرویس نگه دار.

## ۴) ساخت سرویس برای مشتری
1. در «مدیریت کاربران»، نام، مدت روز و حجم GB را وارد کن.
2. خالی‌گذاشتن مدت یعنی بدون انقضا و خالی‌گذاشتن حجم یعنی نامحدود.
3. پس از ساخت، «لینک اشتراک» را باز کن.
4. **صفحه اشتراک** برای مشتری مناسب است: وضعیت سرویس، QR، راهنمای اتصال، عیب‌یابی و لینک برنامه‌های رسمی.
5. **لینک خام اشتراک** را برای Import/Subscription داخل برنامه سازگار بده. لینک اشتراک مثل رمز است؛ فقط به همان مشتری ارسالش کن.
6. غیرفعال‌کردن یا حذف سرویس، دسترسی لینک اشتراک را قطع می‌کند. مصرف و انقضا در پنل پایش می‌شوند.

## ۵) اتصال ربات فروش
1. در بخش «API و اتصال ربات» یک کلید بساز.
2. فقط مجوزهای لازم را انتخاب کن: مشاهده کاربران، مدیریت کاربران، لینک اشتراک، و در صورت نیاز پایش و آمار.
3. کلید خام فقط یک بار نمایش داده می‌شود. آن را در secret/environment variable ربات ذخیره کن.
4. API از `Authorization: Bearer <TOKEN>` استفاده می‌کند؛ مستندات در [API_FA.md](API_FA.md) هستند.
5. اگر کلید افشا شد، آن را فوراً لغو و یک کلید جدید بساز.

## ۶) پروفایل‌ها و پینگ
پروفایل‌های فعلی WebSocket، HTTPUpgrade و چهار حالت XHTTP هستند. آن‌ها از نظر روش انتقال متفاوت‌اند، اما هیچ اسم یا تعداد پروفایلی به‌تنهایی پینگ بهتر را تضمین نمی‌کند. برای بررسی واقعی:
1. یک سرویس آزمایشی بساز و از صفحه اشتراک آن را دریافت کن.
2. با دست‌کم دو کلاینت رسمی، هر شش مسیر را جداگانه آزمایش کن.
3. آزمایش را روی همان سیم‌کارت، منطقه و دستگاه تکرار کن؛ نام اپراتور، نسخه برنامه و خطا را ثبت کن.
4. در صفحه اشتراک «بررسی اتصال» فقط وضعیت پایه را می‌سنجد؛ موفقیت آن اثبات اتصال واقعی تونل نیست.
5. اگر پروفایلی وصل نشد، لاگ‌های Railway و `/data/xray-stderr.log` را بررسی کن. لینک خصوصی و توکن را در گزارش عمومی نگذار.

## ۷) بکاپ و نگهداری
- بکاپ ZIP حاوی دیتابیس، مشتری‌ها، تنظیمات، رویدادها و هش اعتبارنامه‌هاست؛ محرمانه نگهش دار.
- بازیابی، اطلاعات فعلی را جایگزین می‌کند. اول از دیتابیس جاری بکاپ بگیر.
- Volume را حذف نکن؛ حذف آن می‌تواند دیتابیس و کلید نشست را از بین ببرد.
- پس از استقرار نسخه جدید، `/health` را باز کن و سپس ورود، ساخت کاربر، لینک اشتراک، API و پروفایل‌ها را بررسی کن.

## ۸) معنی شاخص‌های داشبورد
- CPU/RAM/disk/load: منابعی که کانتینر می‌بیند؛ لزوماً با کل میزبان یا محدودیت پلن یکسان نیست.
- مصرف ثبت‌شده: داده‌ای که از آمار Xray جمع شده است.
- نرخ ترافیک: تغییر مصرف ثبت‌شده بین دو نمونه‌برداری؛ معیار سرعت‌سنج اینترنت مشتری نیست.
- زمان پاسخ صفحه اشتراک: پاسخ HTTP است، نه پینگ داخل VPN.

## ۹) وضعیت امنیت
تست خودکار، بررسی ایستا و تست مسیرهای برنامه جایگزین تست نفوذ مستقل یا تست شبکه واقعی نیست. پیش از فروش عمومی، دسترسی‌های نقش‌ها، بکاپ/بازیابی، محدودیت نرخ، و اتصال از شبکه‌های هدف را در محیط آزمایشی بررسی کن.
